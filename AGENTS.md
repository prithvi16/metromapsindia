# AGENTS.md

MetroMaps India is an interactive atlas of Indian urban rail: metro, suburban,
monorail, light rail, RRTS, bullet train, tram and water metro. React + MapLibre
app, TypeScript-only scripts, data built from OpenStreetMap and the India Rail
Info atlas.

This file is the contract for coding agents. Read it before changing anything.
`CLAUDE.md`, `.cursor/rules/metromaps.mdc` and
`.github/copilot-instructions.md` point here.

## Commands

```bash
npm install
npm run dev            # Vite on http://localhost:5173
npm run check          # typecheck + lint + data validation + tests (the gate)
npm run build          # typecheck + client bundle + server compile
npm start              # serve dist/ from .build/server.js
```

Data commands:

```bash
npm run data:fetch -- --only=mumbai     # fetch raw OSM into scripts/out/raw
npm run data:build -- --city=mumbai     # rebuild one shard + index + search
npm run data:build                      # rebuild every city that has a raw cache
npm run data:gaps -- --city=mumbai      # prioritised data gaps
npm run validate:data                   # schema-check committed data (no network)
npm run data:geocode -- --city=mumbai --names="A,B"
npm run data:iri -- --city=mumbai
npm run data:suburban -- --city=mumbai
```

`npm run check` must pass before you hand work back. A data change also needs
`npm run validate:data` and, where relevant, `npm run data:gaps -- --city=<slug>`.

For clean JSON on stdout, call a script directly (`npx tsx scripts/report-gaps.ts
--city=mumbai --json`); `npm run` prints its command banner to stdout first.

## Fresh worktree warning

`scripts/out/` is gitignored and does **not** exist in a fresh clone or worktree.
`npm run data:build` therefore has nothing to rebuild and exits with an error
instead of writing an empty dataset. To work on data in a fresh worktree:

```bash
npm run data:fetch -- --only=mumbai
npm run data:build -- --city=mumbai
```

Never bypass the guard with `--allow-shrink` to make a build "work". It exists
to prevent exactly that.

## Layout

```text
src/                 React app (pages, components, lib)
shared/schema.ts     Zod schemas + types: the single data contract
scripts/             TypeScript data pipeline (run with tsx)
  cities.ts          Hand-maintained city registry (bounds, stats, patterns)
  build-cities.ts    Orchestrator: fetch cache -> shards + index + search
  build/             assign, normalize, curate, finalize, dataset writer
  lib/               geo, OSM, stations, preview, suburban, cache, CLI helpers
  curation/          Per-city sourced patches (JSON)
  suburban/          Per-city IRI corridor manifests (JSON)
  out/               Local cache and extracts (gitignored)
data/sources/        Hand-maintained inputs (metro-master.json)
src/data/cities/     Generated output (index.json, search.json, shards/)
docs/                Architecture, pipeline and curation detail
```

## Invariants

1. **Never hand-edit `src/data/cities/index.json`, `search.json` or
   `shards/*.json`.** They are generated by `scripts/build-cities.ts`. Change
   the pipeline or a curation patch and rebuild.
2. **Never invent a station, coordinate, colour, opening date or track.** Every
   coordinate needs a source that was actually opened. Prefer operator
   documents, then government releases, then Wikipedia (for leads, not
   coordinates), then OSM.
3. **One source of truth.** Data types live in `shared/schema.ts`. If you add a
   field, add it to the schema and let `npm run check` catch both sides.
4. **Curation is file-based.** Relation-level fixes, per-line patches, added
   lines and drop rules live in `scripts/curation/<slug>.json`. There is no
   hard-coded curation table.
5. **Warnings are failures.** The build refuses to write when curation or
   suburban assembly reports a warning. Fix the data or pass
   `--allow-warnings` only when the warning is expected and explained in your
   report.
6. **A city build must not touch other cities.** `data:build --city=<slug>`
   rewrites one shard and regenerates the index/search. Do not rewrite unrelated
   shards.
7. **Do not commit `scripts/out/`.** It is cache, not source.
8. **The app must keep working without a network cache.** `npm run build` and
   `npm run validate:data` only read committed files.
9. **Map data is loaded by shard.** A city page loads the city plus
   `neighbours` from the index. Do not reintroduce a single all-cities bundle.
10. **Licensing matters.** Code is MIT. OSM is ODbL. Wikipedia is CC BY-SA.
    India Rail Info data is not open; see `DATA_LICENSES.md` before
    redistributing derived geometry.

## Definition of done

- `npm run check` passes.
- New/changed data has a source URL in the relevant curation/manifest file.
- Generated files were produced by a build, not edited by hand.
- For UI work: `npm run build` passes and the affected page was checked in a
  browser (home, city map, search, or about).
- The final report says what changed, what was verified, what remains
  unresolved, and the exact commands run.
